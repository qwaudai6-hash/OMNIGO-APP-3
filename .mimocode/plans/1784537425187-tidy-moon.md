Generic JWT middleware. Stores `tracking_id` and `role` in `c.Set()`. Modelled on `internal/shared/middleware/admin_auth.go:43`.
```go
package middleware

import (
    "github.com/gin-gonic/gin"
    sharedAuth "github.com/omnigo/backend/internal/shared/auth"
)

const (
    ContextKeyTrackingID = "tracking_id"
    ContextKeyRole       = "role"
)

func JWTAuth() gin.HandlerFunc {
    return func(c *gin.Context) {
        trackingID, role, err := sharedAuth.ParseJWTFromHeader(c.GetHeader("Authorization"))
        if err != nil {
            c.AbortWithStatusJSON(401, gin.H{"error": "UNAUTHENTICATED", "message": err.Error()})
            return
        }
        c.Set(ContextKeyTrackingID, trackingID)
        c.Set(ContextKeyRole, role)
        c.Next()
    }
}

func RoleRequired(roles ...string) gin.HandlerFunc {
    return func(c *gin.Context) {
        got := c.GetString(ContextKeyRole)
        for _, r := range roles {
            if r == got { c.Next(); return }
        }
        c.AbortWithStatusJSON(403, gin.H{"error": "FORBIDDEN_ROLE", "required": roles})
    }
}
```

## §10. ADR Drafts (3-5 architecture decisions)

### ADR-001: Why Go + Rust hybrid (KEEP Go auth, KEEP Rust WS)

**Status:** Accepted
**Date:** 2026-07-20
**Context:** Two parallel implementations of auth + WS gateway exist. Different languages, different teams, different port assignments.

**Decision:** Keep Go for auth-service (port 8080). Keep Rust for websocket-gateway (port 8087). Delete `rust-services/auth-service/` (dormant, only 2 endpoints vs Go's 7+).

**Consequences:**
- Single auth surface = simpler Kong routing, single JWT secret rotation
- Rust WS continues to deliver 10x better concurrency for WebSocket fanout
- Delete dormant code = -600 LOC, simpler CI matrix

### ADR-002: Why outbox pattern (vs direct Kafka publish)

**Status:** Accepted
**Context:** Order creation must atomically write to Postgres AND publish `orders.created` event. Race condition: Kafka publish can fail after DB write succeeds → lost event.

**Decision:** Use outbox pattern. `order_items`, `orders`, and `orders.created` payload inserted in same DB transaction. Background poller reads pending outbox events every 2s, publishes to Kafka, marks processed.

**Consequences:**
- Zero event loss on Kafka outage
- 2s added latency on event delivery
- Outbox table grows; needs periodic cleanup (60s job)

### ADR-003: Why CAS inventory (vs distributed lock)

**Status:** Accepted
**Context:** Flash sale can have 1000 simultaneous requests for last 1 unit. Need atomicity.

**Decision:** `UPDATE products SET stock = stock - $1 WHERE stock >= $1 AND tracking_id = $2`. Postgres row-level lock handles serialization.

**Consequences:**
- No distributed lock service needed (Redlock, etcd, ZooKeeper)
- Postgres writer pool is the bottleneck
- Pattern is portable to MySQL/PostgreSQL/Oracle

### ADR-004: Why Redis Cluster + H3 (vs PostGIS-only)

**Status:** Accepted
**Context:** 10M users, need sub-millisecond proximity search for rider→order assignment.

**Decision:** Redis Cluster with `GEOADD riders:locations <lng> <lat> <rider_id>` for live search. `GEORADIUS ... 5 km` returns eligible riders in <1ms. PostGIS used for historical analytics only.

**Consequences:**
- Live search: O(log N) with H3 ring expansion = fast
- Historical: PostGIS is the source of truth, fed by `graph-sync-worker` from Kafka
- Two systems to maintain; coordination via `location-sync-worker`

### ADR-005: Why double-entry ledger (vs single-account bookkeeping)

**Status:** Accepted
**Context:** Money movement across 4 user types (admin, vendor, rider, customer) and 5 account types (central_escrow, cash_receivable, admin_revenue, vendor_locked_escrow, rider_wallet). Mistakes will lose money.

**Decision:** Every transfer is `from_account → to_account` with HMAC-SHA256 signature, `idempotency_key UNIQUE`, double-entry bookkeeping. TigerBeetle optional for additional double-entry.

**Consequences:**
- Mathematical balance guaranteed at every moment
- Every entry auditable via `SELECT * FROM ledger_entries WHERE ...`
- TigerBeetle not required but available for >10M tx/day
